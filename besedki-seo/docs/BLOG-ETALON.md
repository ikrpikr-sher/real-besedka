# Эталон статьи блога real-besedki.ru

Живой образец: [`/blog/kak-vybrat-besedku-dlya-dachi`](https://real-besedki.ru/blog/kak-vybrat-besedku-dlya-dachi)  
Файл: `content/blog/kak-vybrat-besedku-dlya-dachi.mdx`

Цель — полезный текст для человека на этапе выбора + понятная страница для Google/Яндекс. Не «набить 2000 слов», не doorway по городам.

## Критерии приёмки (все обязательны)

| # | Критерий | Норма |
|---|----------|--------|
| 1 | Объём | **1500–2000 слов** тела (без frontmatter) |
| 2 | Смысл | Блок **описание** → **проблема** → **решение** (заголовки человеческие, не ярлыки «Описание / Проблема») |
| 3 | Польза | Читатель может принять решение или подготовить замер без гуру-воды |
| 4 | Продукт | Каркас 80×80×3, порошок, наши серии; без шатра/мягких окон/чужого SKU |
| 5 | Цены | Только «от» после `npm run sync:katalog`; не выдумывать |
| 6 | Ссылки | 3–6 живых карточек каталога + 2–4 соседние статьи + CTA замер/телефон |
| 7 | Фото | **Свой** набор 4–5 кадров в `public/images/blog/uniq/<slug>/` (обложка + тело), уникальные alt |
| 8 | H1 | Только в шаблоне (`title` frontmatter). В MDX **нет** `#` |
| 9 | Запрет | Markdown-таблицы `| --- |`, сырой pipe-markdown, копипаст абзацев с других постов |
| 10 | FAQ | 4–6 вопросов в frontmatter (для людей и FAQ schema, если подключена) |

## Структура текста (каркас)

1. **Вступление (5–8 предложений)** — боль участка / зачем статья / кто мы одной фразой.
2. **Что это за продукт** (описание) — рамки завода, гео МО, что не продаём.
3. **Где ломается выбор** (проблема) — 4–6 конкретных ошибок с последствиями.
4. **Как выбрать** (решение) — нумерованные шаги: сцена → пятно → контур → каркас → основание → замер/договор.
5. **Бюджет** — как читать «от», что отдельно (сваи, опции).
6. **Стартовые модели** — связным текстом или маркированным списком, **не таблицей**.
7. **Ошибки после монтажа** + мини-чеклист перед звонком.
8. **Итог + внутренние ссылки**.

Тон: прямой, инженерный, без «дизайнерская отделка» вместо стали. Глаголы и гео (Москва/МО).

## Фотоконтент

Папка: `public/images/blog/uniq/<slug>/`

- `01_cover.jpg` — двор, сцена «сесть», не студийный белый фон  
- `02_…` — схема/пятно/сравнение или деталь по теме  
- `03_…` — контур или размер  
- `04_…` — узел/качество (каркас, пол, стекло — по теме)  
- `05_…` — сцена применения (мангал, вечер, замер)

В frontmatter: `coverImage: /images/blog/uniq/<slug>/01_cover.jpg`  
В теле: markdown `![alt по смыслу](/images/...)` — alt описывает кадр, не «иллюстрация к статье».

Генерация/рендер — под **эту** тему; не переиспользовать чужой uniq-файл.

## Чего не усиливать этим эталоном

- Массовые geo-серии вне allowlist МО: `fundament-svai-*`, `zakaz-dostavka-*`, `krovlya-ostekleni-*` — **noindex** (`lib/blogSeoPolicy.ts`), не раздувать до 2000 слов.
- Дубли «город × размер» без новой пользы — схлопывать в хаб или оставлять noindex.
- Страницы, где достаточно карточки каталога — лучше править карточку, не плодить статью.

Сайт №1 = сильное **ядро** + чистый индекс, не 600 одинаковых city-страниц в выдаче.

Сначала очередь **коммерческих** URL (выбор, размер, открытая/закрытая, фундамент, под ключ, сваи-обзор), затем остальные short &lt;1500 слов.

## Гигиена всего корпуса

```bash
python3 scripts/blog-hygiene.py --write   # убрать # H1 из тела, таблицы → списки
```

## Порядок работ на одну статью

1. `npm run sync:katalog` — актуальные `priceFrom`.
2. Замерить текущий объём; выписать 3 боли читателя и 3 решения с нашими моделями.
3. Переписать MDX по каркасу (1500–2000), убрать таблицы и повторы.
4. Собрать 4–5 фото → `public/images/blog/uniq/<slug>/`.
5. Проверка: один H1 на странице, нет `| --- |`, цены = каталог, ссылки 200.
6. Выкладка (блог **не** в rsync):

```bash
scp -i ~/.ssh/besedki_deploy -o IdentitiesOnly=yes \
  content/blog/<slug>.mdx root@31.128.44.47:/var/www/besedki/content/blog/
scp -i ~/.ssh/besedki_deploy -o IdentitiesOnly=yes -r \
  public/images/blog/uniq/<slug> root@31.128.44.47:/var/www/besedki/public/images/blog/uniq/
ssh -i ~/.ssh/besedki_deploy -o IdentitiesOnly=yes root@31.128.44.47 'pm2 restart besedki'
```

7. Через 2–4 недели — смотреть GSC по slug (запросы, клики). Нет данных — не делать вывод о «росте».

## Что эталон даёт и чего не даёт

- **Людям** — порядок выбора и меньше дорогих ошибок.  
- **Роботам** — полноценная страница темы, FAQ, связи с каталогом, уникальные медиа.  
- **Выдаче** — условие роста, не гарантия. Рост проверяется по GSC/Метрике, не обещанием в тексте.
