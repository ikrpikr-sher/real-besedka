# CLAUDE.md — индекс проекта «Дизайнерские беседки»

Читать в начале каждой сессии Claude Code — это карта, а не документация. Работа продолжается по `docs/plan.md`, каждое решение фиксируется в `docs/changelog.md`.

## Что за сайт

SEO-сайт под ключ для бизнеса по проектированию/изготовлению/монтажу дизайнерских беседок (вся Россия, без гео-привязки — если зона монтажа ограничена, см. пометку в `docs/architecture.md`). Собран по методике гайда «Свой SEO-сайт под ключ с Claude Code PRO» (v2.3 PRO).

## Архитектура

Next.js 14, App Router, TypeScript, Tailwind, статическая генерация (SSG). Полная карта страниц — `docs/architecture.md`. ТЗ на сборку — `docs/tz-site.md`. Дизайн-система — `docs/design-system.md`.

## Где что лежит

- `app/` — публичные маршруты (страницы, sitemap.ts, robots.ts)
- `app/admin/` — админка (см. раздел «Админка» ниже). `app/admin/login` — публичный вход, всё остальное — под `app/admin/(protected)/` с проверкой авторизации.
- `app/api/leads/route.ts`, `app/api/admin/**` — API-роуты (приём заявок и CRUD для админки)
- `components/` — переиспользуемые компоненты (Header, Footer, ProjectCard, ArticleCard, LeadForm, FAQ, Breadcrumbs, JsonLd)
- `components/admin/` — компоненты админки (формы, навигация)
- `lib/adminAuth.ts` — авторизация админки (cookie-сессия, пароль из `ADMIN_PASSWORD`)
- `lib/contentStore.ts` — чтение/запись `data/*.json` с диска (используется и публичными страницами, и админкой)
- `lib/seo.ts` — переопределения title/description по маршруту (`data/seo.json`), редактируется в `/admin/seo`
- `data/*.json` — весь табличный контент (проекты, услуги, материалы, о компании, контакты, квиз, seo) — правки через `/admin` или сюда напрямую, не в код
- `data/leads.json` — заявки с сайта (персональные данные — в `.gitignore`, не коммитить)
- `content/blog/*.mdx` — статьи блога (фронтматтер: title, description, date, updated, author, authorRole, category, tags, faq) — правки через `/admin/blog` или напрямую
- `lib/blog.ts` — чтение и фильтрация статей блога
- `seo-agent/semantic-map.json` — карта семантики: кластер → страница-владелец → статус (planned/reserved/published). Контент-фабрика (шаг 6) бронирует кластеры отсюда перед написанием статьи.
- `seo-agent/reports/` — сюда будут падать отчёты SEO-агентов (шаг 5, ещё не настроены — см. «Что не сделано» ниже)
- `docs/research.md`, `docs/architecture.md`, `docs/tz-site.md`, `docs/tz-design.md`, `docs/design-system.md`, `docs/semcore-raw.md` — вся документация шагов 0–2 гайда

## Админка (добавлено 2026-08-07)

По запросу заказчика — полноценная CMS без базы данных: `/admin/*` читает и пишет те же файлы (`data/*.json`, `content/blog/*.mdx`), что рендерят публичные страницы. Никакой БД, никаких новых npm-пакетов (использован уже имевшийся `gray-matter`).

- `/admin/login` — вход по паролю (`ADMIN_PASSWORD` из `.env.local`/переменных окружения хостинга). Сессия — HttpOnly cookie, подписанная HMAC (`ADMIN_SESSION_SECRET`).
- `/admin` — обзор (счётчики заявок/каталога/статей).
- `/admin/leads` — заявки с сайта (статус new/in_progress/done, удаление). Публичный приём — `POST /api/leads`, форма (`LeadForm.tsx`) теперь реально шлёт туда данные вместо TODO-заглушки.
- `/admin/catalog/proekty`, `/uslugi`, `/materialy` — CRUD по каждому типу каталога.
- `/admin/blog` — CRUD статей (создаёт/переписывает `.mdx`-файлы с фронтматтером через `gray-matter`), включая редактор FAQ.
- `/admin/seo` — title/description для статических страниц (главная, категории, контакты и т.п.), хранится в `data/seo.json`, применяется через `generateMetadata()` в соответствующих `page.tsx`.
- Всё под `/admin/*` и `/api/*` закрыто от индексации (`robots.ts`, `noindex` в layout админки).

**Важно для деплоя:** так как `/admin` пишет файлы на диск во время запроса, `output: 'export'` в `next.config.mjs` убран — сайт больше не может быть чисто статическим. Нужен Node.js-хостинг (см. «Как деплоить»).

Перед первым входом смените `ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET` — стартовые значения в `.env.local` временные (см. `docs/next-steps-prompts.md`).

## Как запускать

```
npm install
npm run dev     # локальная разработка
npm run build   # проверка сборки (ОБЯЗАТЕЛЬНО перед деплоем)
```

Перед первым запуском создайте `.env.local` в корне проекта (см. `.env.local.example`-инструкцию в `docs/next-steps-prompts.md`) — без `ADMIN_PASSWORD` вход в `/admin` не откроется (это ожидаемо и безопасно, а не баг).

## Как деплоить

Хостинг — **Beget**, но не shared-статика, а **Node.js-приложение** (решение изменилось 2026-08-07: изначально планировали `next export` на обычный shared-хостинг, но после добавления `/admin`, который пишет файлы на диск по запросу, статический экспорт больше не подходит — нужен постоянно работающий Node.js-процесс).

```
npm install
npm run build   # обычная сборка Next.js (.next/), НЕ export — папки out/ больше не будет
npm run start   # запуск production-сервера (Beget управляет процессом сам через свою панель Node.js-хостинга)
```

На Beget: раздел «Node.js» в панели (не «Сайты» → обычный shared) — там указывается команда запуска (`npm run start` после `npm run build`) и переменные окружения (`ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` — обязательно, иначе `/admin` не заработает). Подробный промпт для этого шага — `docs/next-steps-prompts.md`.

Форма заявки (`LeadForm.tsx`) теперь работает «из коробки» — шлёт на `POST /api/leads`, заявки видно в `/admin/leads`. Уведомления в Telegram/почту при новой заявке — не сделаны, можно добавить отдельным шагом (дописать отправку в `app/api/leads/route.ts`).
